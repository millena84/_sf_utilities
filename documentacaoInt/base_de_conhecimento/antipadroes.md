# Anti-padrões e riscos

> Gerado a partir de `_fonte/`. Não edite este arquivo: altere as definições e rode `python3 _fonte/render.py .` nesta pasta.

O que a documentação de uma integração deve sinalizar como risco. Recomendações do Salesforce Well-Architected e dos guias oficiais (consultados em 2026-10-30); citações entre aspas são literais.
Ao documentar: registre o anti-padrão na seção de pontos em aberto, com a evidência `arquivo:linha`, sem copiar valores sensíveis.

| ID | Anti-padrão | Como detectar no projeto | Risco | Recomendação | Fonte |
|---|---|---|---|---|---|
| A01 | Segredo no código ou em configuração versionada | senha/token/client_secret literal em Apex; `values` de Custom Metadata, Custom Setting ou Custom Label com segredo (E4/E6) | vazamento por repositório, logs e mensagens de erro | "Never embed credentials in code, configuration files, or version control. Use named credentials and external credentials" | [WA-TRUST](https://architect.salesforce.com/docs/architect/well-architected/guide/trust.html) |
| A02 | URL fixa no código | C03 `setEndpoint('https://...')` literal + Remote Site Setting (E3) | troca de ambiente exige deploy; credencial costuma ir junto no código | autenticação e endpoint centralizados em Named Credential / External Credential | [WA-TRUST](https://architect.salesforce.com/docs/architect/well-architected/guide/trust.html), [AX-NC](https://developer.salesforce.com/docs/atlas.en-us.apexcode.meta/apexcode/apex_callouts_named_credentials.htm) |
| A03 | Fluxo OAuth Username-Password | não aparece no XML do app (N11); procurar no código/config do cliente ou documentação do sistema externo | fluxo bloqueado por padrão em orgs criadas a partir do Summer '23 e com aposentadoria publicada | "Do not use the Username-Password Flow"; usar JWT Bearer (servidor-servidor) ou outro fluxo adequado | [WA-TRUST](https://architect.salesforce.com/docs/architect/well-architected/guide/trust.html) |
| A04 | Um app (Connected App/ECA) compartilhado por várias integrações | vários sistemas externos descritos com o mesmo `consumerKey`/app; escopos amplos (`scopes`/`commaSeparatedOauthScopes` com `Full`) | um token comprometido alcança tudo; auditoria confusa | "One registration per integration"; escopos mínimos; preferir External Client App em integrações novas | [WA-TRUST](https://architect.salesforce.com/docs/architect/well-architected/guide/trust.html) |
| A05 | Usuário de integração com permissões demais ou compartilhado com pessoas | Profile/Permission Set do usuário de integração com Modify All/View All; ausência de API Only | acesso indevido e falta de rastreabilidade | usuário de integração dedicado, API Only, Permission Sets de menor privilégio; "Minimum Access - API Only Integrations" em builds novos | [WA-TRUST](https://architect.salesforce.com/docs/architect/well-architected/guide/trust.html) |
| A06 | Callout síncrono em trigger | S08: C02 no contexto do trigger sem async | callout não permitido em trigger (falha em execução) | "Callouts must be made asynchronously from a trigger" | [AX-TRG](https://developer.salesforce.com/docs/atlas.en-us.apexcode.meta/apexcode/apex_triggers.htm) |
| A07 | Callout depois de DML na mesma transação | DML (`insert`/`update`) antes de C02 no mesmo método/transação | erro de operação pendente (uncommitted work) | fazer o callout antes do DML ou mover para async | [AX-LIM](https://developer.salesforce.com/docs/atlas.en-us.apexcode.meta/apexcode/apex_callouts_timeouts.htm) |
| A08 | Callout sem timeout definido ou sem orçamento de tempo | C02 sem C05 `setTimeout`; vários callouts em sequência na mesma transação | padrão de 10 s pode ser curto; soma limitada a 120 s por transação | "Configure appropriate timeouts for all integration callouts" e orçar os 120 s | [WA-REL](https://architect.salesforce.com/docs/architect/well-architected/guide/reliability.html), [AX-LIM](https://developer.salesforce.com/docs/atlas.en-us.apexcode.meta/apexcode/apex_callouts_timeouts.htm) |
| A09 | Falha sem retry ou retry sem critério | async sem Finalizer (C10), sem fila (G.1) e sem tratamento de status HTTP; ou retry imediato em loop | perda silenciosa de mensagens ou tempestade de retries | retry com backoff exponencial; não repetir 4xx (exceto 429); reenfileirar em async após erro de limite; fila em Platform Event ou objeto | [WA-REL](https://architect.salesforce.com/docs/architect/well-architected/guide/reliability.html) |
| A10 | Sem circuit breaker em integração instável | muitos callouts ao mesmo host sem checagem de estado | timeouts em cascata consomem tempo e limites | circuit breaker com estado em Platform Cache e Platform Events para propagar | [WA-REL](https://architect.salesforce.com/docs/architect/well-architected/guide/reliability.html) |
| A11 | Sem log nem correlação | nenhum objeto de log (`__c`), nenhum ID de correlação no payload | falhas passam despercebidas; diagnóstico difícil | registrar início/fim, contagens, erros e IDs de correlação; monitorar sucesso, latência e retries | [WA-OPS](https://architect.salesforce.com/docs/architect/well-architected/guide/operational-excellence.html) |
| A12 | Processamento não idempotente | Batch/Queueable que reenvia sem chave (sem External ID/upsert, sem status de envio) | duplicidade em reprocessamento | "Batch jobs implement idempotency and comprehensive logging"; upsert por External ID | [WA-OPS](https://architect.salesforce.com/docs/architect/well-architected/guide/operational-excellence.html) |
| A13 | Writeback sem proteção contra recursão | trigger que enfileira callout e depois atualiza o mesmo objeto sem flag/campo de controle | loop de execuções e consumo de limites assíncronos | campo de controle ou guarda estática antes de reenfileirar | heurística |
| A14 | Recursos legados em integração nova | Workflow com `outboundMessages` (D.4); Named Credential `namedCredentialType`=Legacy; Connected App nova | manutenção e suporte decrescentes | Flow, Named Credential com External Credential e External Client App (criação de Connected App nova desabilitada por padrão desde o Spring '26) | [WA-TRUST](https://architect.salesforce.com/docs/architect/well-architected/guide/trust.html), [MA-NC](https://developer.salesforce.com/docs/atlas.en-us.api_meta.meta/api_meta/meta_namedcredential.htm) |
| A15 | Webhook público sem validação | S31 (Site + Apex REST) sem verificação de assinatura/token no código | qualquer um na internet pode chamar o endpoint | validar assinatura; evitar guest user para ações de backend (usar usuário de integração dedicado) | [WA-TRUST](https://architect.salesforce.com/docs/architect/well-architected/guide/trust.html) |
| A16 | Certificado autoassinado em produção | `certs/*.crt` usado por Named Credential/app de integração de produção | quebra a cadeia de confiança com clientes externos | "Production integrations require certificates that are signed by trusted Certificate Authorities" | [WA-TRUST](https://architect.salesforce.com/docs/architect/well-architected/guide/trust.html) |
| A17 | Remote Site com `disableProtocolSecurity`=true | `remoteSiteSettings/*.remoteSite` | dados podem trafegar de HTTPS para HTTP | manter false; usar só HTTPS | [MA-RSS](https://developer.salesforce.com/docs/atlas.en-us.api_meta.meta/api_meta/meta_remotesitesetting.htm) |
| A18 | Muitos jobs assíncronos por registro | trigger que enfileira um future/Queueable por registro, sem agrupar | consome o limite diário de execuções assíncronas e de enfileiramento (50 por transação síncrona) | agrupar registros por job; Batch para volume | [AX-GOV](https://developer.salesforce.com/docs/atlas.en-us.apexcode.meta/apexcode/apex_gov_limits.htm) |
